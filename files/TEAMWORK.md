# 가변 총괄 AI 협업 규칙

이 문서는 Claude와 Codex가 함께 사용하는 공통 협업 정책입니다. 작업자 생성, 메시지,
질문·답변, 완료·실패 추적과 정리는 설치된 Orca 공식 `orchestration` 스킬에 맡기고,
이 문서에는 역할, 배치, 안전 경계와 검증 기준을 정합니다.

이 정책은 여러 에이전트를 사용하거나 작업을 다른 에이전트에게 인계할 때만 적용합니다.
한 명의 에이전트가 직접 끝낼 수 있는 일반 작업에는 불필요한 작업자를 만들지 않습니다.

이 문서의 **총괄(lead)** 은 Orca의 Coordinator와 같은 역할이며 최종 판단, 변경 통합,
검증 확인과 사용자 보고를 맡습니다. **보조/검토**는 Orca가 Dispatch한 Worker와 같은
역할입니다. 중요한 범위·병합·배포 결정의 최종 승인자는 사용자입니다.

## 작업 시작

총괄은 실제로 여러 작업자를 사용할 때만 다음 내용을 짧게 알리고 바로 진행합니다.

```text
총괄: Claude | Codex
보조/검토: Claude | Codex | 같은 종류 여러 명 | 없음
목표와 완료 기준:
수정 가능 범위:
위험도: 보통 | 중요 | 고위험
배치: 현재 작업공간 | 기존 작업공간 | 새 작업트리
선택한 모델/추론 수준: 기본값 | low | medium | high
```

- 코드 구현, 버그 재현, 테스트, 리팩터링과 저장소 조사 중심 작업은 Codex를 총괄 후보로 우선 고려합니다.
- 제품 기획, 사용자 흐름, 문서 의도, 브랜드와 문장 판단 중심 작업은 Claude를 총괄 후보로 우선 고려합니다.
- 두 성격이 섞인 작업은 가장 큰 불확실성이 있는 영역에 맞춰 총괄을 정합니다.
- 사용자가 총괄이나 작업자를 지정하면 그 선택을 우선합니다.
- 사용자가 역할과 순서를 정하지 않았으면 총괄이 작업 성격에 따라 스스로 결정합니다.

## 공식 Orca 기능과 연결

- 총괄이 결과를 기다리고 질문에 답하며 최종 통합하는 협업은 공식 `orchestration` 스킬을 사용합니다.
- 감독 없이 다른 에이전트나 작업트리에 완전히 넘기는 요청은 `orca-cli`의 handoff를 사용합니다.
- Run, Task, Dispatch, 메시지, `worker_done`, 복구와 정리는 설치된 Orca 버전의 공식 가이드를 따릅니다.
- 정책 문서만 읽고 작업자를 실제로 만들지 않은 상태를 오케스트레이션 완료로 보고하지 않습니다.

## 작업자 시작과 작업공간 신뢰 자동 승인

- 사용자는 Orca에 등록한 로컬 프로젝트와 그 Git 작업트리를 Claude와 Codex가 사용하는 것을 기본 승인했습니다. 총괄은 작업자를 실행하기 전에 `orca repo list`와 작업트리 정보로 현재 경로가 등록된 저장소에 속하는지 확인하고, 해당 제공자가 지원하는 로컬 신뢰 저장소에 원본 저장소 루트를 미리 등록합니다. Claude는 해당 프로젝트의 `hasTrustDialogAccepted`를, Codex는 해당 프로젝트의 `trust_level`을 신뢰 상태로 기록합니다.
- 사전 등록 범위는 Orca에 현재 등록된 저장소와 그 저장소에서 파생된 Git 작업트리로만 제한합니다. 임의 폴더, 사용자 홈 전체, 외부에서 받은 미검증 폴더를 포괄 승인하지 않습니다.
- 총괄이 Orca에서 Claude 또는 Codex 작업자를 시작하거나 기존 작업공간에 연결한 직후에는 작업자 터미널의 실제 렌더링 화면을 먼저 읽습니다. 화면을 `입력 준비`, `작업공간 신뢰 확인`, `로그인·보안 확인`, `오류 또는 셸로 종료` 중 하나로 판별하기 전에는 작업 프롬프트를 보내거나 같은 작업자를 다시 시작하지 않습니다.
- 작업공간 신뢰 확인창이 나타나면 화면에 표시된 절대 경로를 Orca가 해당 터미널에 대해 보고한 `worktreePath`와 대소문자, 경로 구분자와 끝 구분자를 정규화해 비교합니다. 두 경로가 정확히 같고 현재 Orca가 관리하는 프로젝트 또는 작업공간임이 확인될 때만 신뢰 항목을 자동 승인합니다.
- Claude의 `Accessing workspace` 화면에서는 실제 렌더링 화면에서 `Yes, I trust this folder`를 확인한 뒤 방향키로 그 항목을 선택하고 Enter를 한 번 누릅니다. Codex에서 프로젝트 또는 디렉터리 신뢰 화면이 나타나면 같은 검증을 거쳐 화면에 표시된 신뢰 항목을 선택합니다. 숫자 입력이나 고정된 키 순서를 추측하지 않습니다.
- 경로가 다르거나, 상대 경로만 보이거나, `worktreePath`를 확인할 수 없거나, Orca가 관리하지 않는 폴더라면 자동 승인하지 않고 멈춰 사용자에게 알립니다.
- 이 자동 승인은 검증된 작업공간을 신뢰할지 묻는 최초 확인에만 적용합니다. 로그인, 2차 인증, 계정 변경, 명령 실행, 파일 외부 접근, 훅, 결제, 배포, 삭제와 기타 권한 확인은 자동 승인하지 않습니다.
- Claude의 `--dangerously-skip-permissions`·`bypassPermissions`, Codex의 `--dangerously-bypass-approvals-and-sandbox`·`--yolo`·`--dangerously-bypass-hook-trust`처럼 다른 안전 확인까지 끄는 옵션을 이 문제의 해결책으로 사용하지 않습니다.
- 승인 뒤 작업자 입력창이 실제로 준비됐는지 다시 확인하고 작업 요청을 한 번만 전달합니다. 신뢰 화면에서 프로세스가 셸로 돌아왔다면 성공으로 간주하지 않으며, 원인을 확인한 뒤 같은 터미널에서 한 번만 다시 시작합니다. `existing workspace` 연결과 새 작업자 생성을 번갈아 반복하거나 중복 작업자·중복 작업을 만들지 않습니다.

## 작업자 선택과 위임

- 총괄과 다른 종류의 에이전트를 의무적으로 열지 않고 하위 작업 성격에 맞춰 선택합니다.
- 구현·테스트·저장소 조사는 Codex 작업자를, 제품 의도·사용자 흐름·문서 검토는 Claude 작업자를 우선 고려합니다.
- 독립 검토가 중요하면 총괄과 다른 종류의 에이전트를 우선 고려합니다.
- 독립적으로 끝내고 검증할 수 있는 하위 작업만 위임합니다.
- 각 작업자에게 목표, 파일 범위, 금지 범위, 소유권과 관찰 가능한 완료 증거를 분명히 줍니다.
- 총괄은 작업자의 실제 결과와 완료 증거를 확인한 뒤에만 최종 완료를 보고합니다.
- 작성자가 자신의 결과만 다시 읽은 것은 독립 검토로 보지 않습니다.

## 작업공간과 동시 수정

- 읽기·조사·검토 또는 수정 파일이 겹치지 않는 작업은 같은 작업공간에서 진행할 수 있습니다.
- 같은 파일을 수정할 가능성이 있거나 위험한 실험, 장기 기능, 별도 브랜치가 필요하면 새 작업트리를 고려합니다.
- 같은 작업공간에서는 두 에이전트가 같은 파일을 동시에 수정하지 않도록 소유 범위를 나눕니다.
- 검토 전용 작업자는 파일을 수정하지 않습니다.
- 새 작업트리는 직접 덮어쓰기를 막을 뿐 병합 충돌까지 없애지는 않습니다. 총괄이 최종 통합과 검증을 맡습니다.

## 사용자 승인과 안전 경계

- 보통 위험의 작업은 불필요한 승인 절차를 늘리지 않고 완료 시 변경과 검증 결과를 보고합니다.
- 아키텍처, 보안, 개인정보, 데이터, 배포, 비용, 권한 또는 되돌리기 어려운 변경은 실행 전에 영향과 복구 방법을 설명하고 승인을 받습니다.
- 로그인 정보, 비밀번호, 인증 코드, API 키, 쿠키를 요청·저장·출력하지 않습니다.
- 새 로그인, 로그아웃, 계정 추가·삭제, 결제, 구독 변경과 2차 인증은 사용자가 직접 처리합니다.
- 사용자가 승인하지 않은 고위험 변경을 완료·병합·배포된 것으로 보고하지 않습니다.

## 범위·병렬·재시도 제한

- 동시에 실행하는 보조 작업자는 기본 3명 이하로 둡니다.
- 자동 재시도는 기본 1회만 허용하며 같은 오류를 같은 방식으로 반복하지 않습니다.
- 중첩 위임은 공식 기능이 지원할 때만 사용하고 깊이는 2단계 이하로 제한합니다.
- 예상 시간, 사용량 또는 변경 범위를 크게 넘으면 이유와 영향을 보고합니다.
- 공식 orchestration이 더 엄격한 제한을 정하면 공식 제한을 우선합니다.

## 모델과 추론 수준

- 이 기준은 Claude와 Codex에 똑같이 적용하되 각 앱과 계정에서 실제 제공하는 모델과 단계만 사용합니다.
- 기본값은 현재 세션 모델과 `medium` 추론 수준입니다.
- `low`는 범위가 명확한 읽기·검색·반복 작업에 사용합니다.
- `high`는 설계 판단, 복잡한 오류 분석, 보안·데이터 위험 검토 또는 반복 실패에 사용합니다.
- 실행 중인 작업자의 모델과 추론 수준은 중간에 바꾸지 않습니다. 필요하면 결과를 정리하고 새 작업자를 시작합니다.

## Codex 계정 자동 전환

계정 자동 전환은 이 공유 정책의 기본 기능입니다. 다음 범위 안에서만 실행합니다.

- Codex 사용량 경고가 표시되거나 현재 계정으로 작업을 계속할 수 없으면 먼저 목표, 확정한 결정, 수정 파일, 검증 결과와 남은 일을 인계 요약으로 만듭니다.
- Orca에 이미 연결되고 인증이 끝난 다른 Codex 계정의 사용 가능 상태가 화면에서 명확히 확인되면 공식 `computer-use` 스킬로 `설정 → AI 제공자 계정 → Codex`를 열어 사용 가능한 계정으로 전환할 수 있습니다.
- 사용자가 특정 계정을 지정했거나 자동 전환을 금지했다면 그 지시를 우선합니다.
- 전환은 이미 인증된 계정 행을 선택하는 동작으로만 제한합니다.
- 사용할 계정이나 사용 가능 상태가 불분명하거나 로그인·2차 인증·보안 확인 화면이 나타나거나 `computer-use`를 사용할 수 없으면 임의로 선택하지 않고 멈춰 사용자에게 필요한 조치를 알립니다.
- 전환 뒤 선택한 계정이 활성 상태인지 확인하고 새 Codex 작업자를 시작해 인계 요약을 전달합니다.
- 이전 작업자는 중복 실행하지 않으며 새 작업자의 시작을 확인한 뒤에만 작업을 재개합니다.
- 완료 보고에는 자동 전환 성공·실패와 인계 범위를 포함하되 계정 이메일, 로그인 정보와 구체적인 사용량 수치는 노출하지 않습니다.

자동 전환을 사용하려면 사람이 먼저 Orca에 둘 이상의 Codex 계정을 로그인·연결하고,
공식 `computer-use` 스킬을 사용할 수 있게 설정해야 합니다. 이 준비가 되지 않은 환경에서는
자동 전환을 시도하지 않고 사용자 안내로 전환합니다.

## 완료 보고

- 완료 보고에는 구현한 것, 변경 이유, 실행한 검증, 검증하지 못한 것과 남은 위험을 포함합니다.
- 터미널이나 작업자가 살아 있다는 신호만으로 완료를 판단하지 않습니다.
- 실제 변경, 테스트 결과, 산출물 또는 구조화된 `worker_done`을 확인합니다.
- 모든 작업자는 완료 후 공식 절차에 따라 재사용, 유지 또는 해제 상태를 분명히 정리합니다.
